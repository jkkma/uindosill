# What the bundled Python carries, pinned.
#
# Every version here is one this project has measured against, and **every line carries one** —
# an unpinned line in a file whose whole argument is pinning is a hole with a promise over it.
# Loosening one is a decision to be recorded rather than a convenience: a resolver picking something
# newer at package time would ship a stack nobody scored.
#
# **What "measured against" means differs by line, and the difference is worth stating.** The
# execution-provider arms of 2026-08-21 ran on exactly these versions. The translator's
# 8,149-sentence gate of 2026-08-20 did **not**: it ran on `onnxruntime` 1.29.0, on the CPU, as its
# own `translation-quality.json` records under `producedBy`. What carried across unchanged from it
# are CPython 3.12.10 and the three packages that decide the decode — torch 2.13.0,
# transformers 4.57.6, optimum 2.1.0. The runtime did not, and **the gap that leaves is measured
# rather than assumed**: on 2026-08-21 `scripts/measure-translation-agreement.ps1` put the whole
# gate corpus back through these versions and got **8,149 of 8,149 recorded hypotheses back
# character for character**, all 24 languages at 100%, on WebGPU against the gate's CPU.
#
# The CPython 3.14 stack in `tests/fixtures/translation/marian-tokenizer.json` is a different
# artefact's — the tokenizer fixture and the export, not the gate — and this comment claimed it as
# the gate's until 2026-08-21.
#
# **onnxruntime-webgpu, not onnxruntime.** It carries the CPU provider as well, so this one wheel is
# both shipping providers. Measured 2026-08-21 on AMI test, WebGPU scores 16.3319% against the CPU's
# 16.3324% — a difference of 0.0005 points — which is what makes it selectable automatically; CUDA
# is faster and moves the number, and would cost about 1.65 GB of CUDA and cuDNN libraries besides.
#
# **1.27.0 rather than the 1.29.0 this repository pins for .NET**, because that is the newest release
# `onnxruntime-webgpu` is published at. The version costs nothing here: measured 2026-08-21, the
# diariser's parity fixture on cpu@1.27.0 against cpu@1.29.0 is 0.000e+00 — bit-identical.
onnxruntime-webgpu==1.27.0

# **torch is the CPU build and stays the CPU build.** It is here because `transformers.generate`
# needs it and because the diariser calls NVIDIA's own SortformerModules, which is torch code; no
# graph runs on it. That also means IO binding is off in the translator — `optimum` binds a KV cache
# to a torch device — and the published 0.459 s/sentence WebGPU figure is a binding-off figure, so
# it is a floor rather than a ceiling.
#
# On Windows the default PyPI wheel is the CPU build. On Linux it is not, and a bundle built there
# would silently pull about 2 GB of CUDA libraries, so the index is named rather than assumed.
--extra-index-url https://download.pytorch.org/whl/cpu
torch==2.13.0

optimum-onnx==0.1.0

# The diariser: soundfile reads the 16 kHz mono WAV the host writes.
#
# **librosa is gone as of 2026-08-26, and with it about 330 MB.** It was here for exactly one call,
# `librosa.filters.mel`, which built the mel filterbank matrix -- and that call dragged in numba,
# llvmlite, pooch, audioread and `soxr`. `diariser/feats.py` now loads that matrix from a committed
# `mel-filterbank.npy` generated by this same librosa 1.0.0 at the same parameters.
#
# **The fidelity argument this line used to carry is what made the change safe rather than what
# blocked it.** feats.py was the spike's file byte for byte so that the measured 16.3324% AMI
# figure would describe it. Checked before the edit: the matrix is deterministic, round-trips
# through `.npy` bit-for-bit, and the mel features on sixty seconds of real audio are *bit-identical*
# either way -- verified again after, old code against new, same 6016x128 array to the last bit. A
# committed array pins what a library call could drift from, so the figure describes this code more
# tightly than it did.
#
# **It also removed the product's only statically-linked LGPL binary.** `soxr` came in only because
# librosa declared it; its libsoxr is inside `soxr_ext.pyd`, which is what LGPL-2.1 section 6(b)
# cannot cover. libsndfile stays -- soundfile genuinely reads every WAV -- and it is a separate,
# replaceable DLL. `licences/LGPL-WRITTEN-OFFER.txt` and `docs/LICENSING.md` carry the reading.
soundfile==0.14.0
numpy==2.5.2

# The second diariser (pyannote.audio), which replaced DiariZen on 2026-08-27. **Its size on disk
# has not been measured**; the number that stood here for the arm it replaced was 242 MiB of
# site-packages and it does not transfer, because this stack's dependency set is a different one.
#
# **Why a replacement and not an addition.** DiariZen vendors a fork of pyannote-audio 3.1.1 and
# pyannote's own release line is at 4.x, and the two cannot share an interpreter. It is not only
# the `pyannote.audio` name: 4.0.7 floors `pyannote.core>=6.0.1`, `pyannote.database>=6.1.1`,
# `pyannote.metrics>=4.0.0` and `pyannote.pipeline>=4.0.0`, against the 5.0.0, 5.1.3, 3.2.1 and
# 3.0.1 the fork needs. Five shared import names, five incompatible floors, one environment. The
# vendored fork and DiariZen's own source moved to `attic/diarizen/` with the engine.
#
# **What is gained is a licence, and it is the reason the swap is worth making.** DiariZen's weights
# are CC BY-NC 4.0 — the only non-commercial licence this product carried. `speaker-diarization-community-1`
# is CC BY 4.0. The algorithm is the same family either way: pyannote 4 clusters with VBx,
# contributed by the same BUT Speech@FIT researchers who publish DiariZen.
#
# **torchcodec comes with it and should never be called — read off upstream's source, not observed.**
# `pyannote.audio` requires `torchcodec>=0.7.0` for decoding, and TorchCodec decodes through FFmpeg
# — the LGPL component this product removed in 1702d9e. It does **not** bundle one: its own PyPI
# description says "TorchCodec uses the version of FFmpeg you already have installed", so the wheel
# carries no FFmpeg binary and installing it redistributes no LGPL object. On a machine without
# FFmpeg its import raises, `pyannote/audio/core/io.py` catches that in its own guard, and the
# waveform route is the only one left — which is the route `diariser/pyannote_engine.py` uses
# unconditionally anyway. `docs/LICENSING.md` carries the finding.
#
# **speechbrain is still deliberately NOT here.** pyannote imports it inside a `try/except
# ImportError` for a speechbrain-hosted embedder this project does not use -- it uses the pyannote
# one -- so its absence costs nothing and sets `SPEECHBRAIN_IS_AVAILABLE = False`, which is the path
# upstream wrote for exactly this case. The two failure modes that made it unusable under the
# previous stack are recorded in `docs/GOTCHAS.md`; nothing about 4.x invites revisiting it.
#
# **Nothing here has been resolved against the other pins, and that is the open risk.** The
# translator holds `huggingface-hub<1.0` through transformers 4.57.6 and pins numpy 2.5.2 and torch
# 2.13.0; `pyannote.audio` 4.0.7 floors `torch>=2.8.0` and `huggingface-hub>=0.28.1`, which is
# compatible on its face and has **not** been run through a resolver here. Assembling the bundle is
# what settles it, and `docs/UNPROVEN.md` carries the gap until it does.

# torchaudio must match torch 2.13.0 above; 2.11.0 is what that pairs with, and it is pinned like
# everything else here rather than left to the resolver. **pyannote.audio uses it for resampling and
# for `compliance.kaldi` features, both pure torch**; its `load` is not on any path this project
# reaches, which is why no shim replaces it — see `diariser/pyannote_engine.py` for why the one that
# used to be there was removed rather than carried over. The comment here named
# `diariser/diarizen.py` until 2026-08-27, which is a file that has moved to `attic/`.
torchaudio==2.11.0

# transitive line is the hole this file's header warns about; pinning it costs nothing and keeps the

# graph an exporter would produce stays reproducible if one returns, and because dropping it is a
# resolver change that cannot be verified without assembling the bundle — which has not been done
