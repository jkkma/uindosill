# The bundled Python's transitive closure, pinned.
#
# WHAT THIS IS. `requirements-bundle.txt` pins the 26 packages this product asks for. It pins
# nothing they in turn depend on, so the other 83 distributions in the bundle floated: whatever pip
# resolved on the day. This file is the whole closure at the versions the shipping bundle was built
# from, 106 entries covering those 83 and the 23 direct pins that are not torch, and it is applied
# as a pip CONSTRAINTS file rather than as a requirements list. Constraints bind a version if a
# package is installed and never cause one to be installed, so this cannot quietly add anything to
# the bundle. The direct pins are repeated here rather than left out because a constraints file is
# read on its own, and one that silently declined to bind 23 of the 109 would be the more
# surprising of the two.
#
# WHY. The float cost three things on 2026-08-29, all in one afternoon:
#
#   * v1.0.0-rc.7's release job died after 30 minutes on the bundled-Python notice check, because
#     kiwisolver went 1.5.0 to 1.5.1 between one release and the next.
#   * The CUDA pack rebuilt from identical pins produced a zip 27,649 bytes larger with a different
#     SHA-256 and an unchanged torch, so its pinned digests could not be reproduced, only read off
#     whatever had shipped.
#   * The win-cuda installer grew 100,079 bytes against a margin of 141.7 MiB under GitHub's
#     per-asset limit, which is the margin rc.4 already died at twice.
#
# WHAT IS DELIBERATELY ABSENT. torch, torchaudio and torchcodec. Those three are the only entries
# carrying a local version suffix (`+cpu` here, `+cu130` in the CUDA pack), and the suffix is chosen
# by the index the install runs against, not by this repository. Constraining them would pin the
# CPU build into a pack whose entire purpose is to be the CUDA one. Their VERSIONS are pinned where
# they belong, in `requirements-bundle.txt`, and `CudaPackInstaller` checks the pair at install.
#
# WHAT THIS DOES NOT CATCH. A genuinely NEW transitive package. Constraints do not forbid one, and
# an unconstrained arrival would install at its latest version. That is caught one step later and
# loudly: `scripts/collect-python-notices.py --check` compares NOTICE.md against the bundle and
# fails the release, which is the right place for it, because a new distribution is a new licence
# and wants a human rather than a pin.
#
# REGENERATE with `scripts/bundle-python.ps1 -WriteLock`, which writes this file from the bundle it
# just assembled. Do that when a direct pin in `requirements-bundle.txt` moves, and re-run
# `scripts/collect-python-notices.py` in the same commit so NOTICE.md and this file describe one
# bundle.
